# Languages

The app is available in English (`en-CH`), German (`de-CH`), French (`fr-CH`) and
Italian (`it-CH`). The identifier is a Swiss locale, so one value picks the
translations **and** how numbers and dates are written: `1'234.50` / `5.9.2026` in
German, `1 234,50` / `05.09.2026` in French, `1'234.50` / `05/09/2026` in Italian.
Money is always written `Fr. 1'234`, in every language.

## How it works

- The language is saved in the Setting table (`language`), not in the browser: the
  desktop app's origin changes on every launch. Until one is chosen, the window's
  `Accept-Language` (which follows the operating system) decides, English if nothing
  matches. Picked on the first screen of the setup and under Settings → Appearance
  (`PUT /api/language`).
- The root layout loads the language and its messages per request and hands them to
  `<I18nProvider>` (`src/lib/i18n/provider.tsx`); `<html lang>` follows. Changing the
  language calls `router.refresh()`, so the page re-renders in place.
- Only the language in use is sent to the browser (`loadMessages` in
  `src/locales/index.ts`).
- Pure parts: `src/lib/i18n/translate.ts` (lookup, `{placeholders}`, plurals, `<tags>`),
  `format.ts` (numbers, dates, lists), `locales.ts` (the languages, matching).

## Using it

```tsx
const { t, rich, f, locale } = useT()

t("settings.title")                              // plain
t("settings.age", { age: 31 })                   // {age} is filled in
t("import.rejected", { count: 3 })               // plural: "import.rejected#one" / "#other"
rich("dashboard.noBudgets", {                    // "…<link>Set budgets</link>…"
  link: text => <a href="/budgets">{text}</a>,
})
f.int(1234)  f.decimal(1234.5)  f.percent(0.049)  f.date(d)  f.monthLong("2026-09")  f.list(["A", "B"])
```

Server code (routes, server components) uses `getT()` from `src/lib/i18n/store.ts`.

Keys are `area.thing`. A message with a count has one key per plural form
(`x#one`, `x#other`); the code asks for `x` and the language's own plural rules pick
the form.

## Adding or changing text

1. Add the key to `src/locales/en-CH.ts`.
2. Add it to `de-CH.ts`, `fr-CH.ts` and `it-CH.ts`. TypeScript fails the build if one
   is missing or extra.
3. `pnpm i18n:check` verifies each translation keeps English's `{placeholders}` and
   `<tags>` and that plural forms exist for the language.

Text that **is data** stays as it is: category names, counterparties, booking texts,
the note saved with a snapshot, bank and broker names.

## Adding a language

Add the locale to `LOCALES` / `LOCALE_NAMES` (`src/lib/i18n/locales.ts`), a file
`src/locales/<locale>.ts` typed `Dict`, and a `case` in `loadMessages`. Languages
with more plural forms (e.g. Polish) add the keys they need (`.few`, `.many`).

## Coverage

Every page and component is translated, including the labels the libs define (goal
kinds, asset and liability kinds, category types, rule options: the libs keep the
identifiers, the words live in `src/locales`), the portfolio warnings (the engine
returns data, `warningText` words it) and the errors a person can run into when
importing a file or restoring a backup.

Stays as it is:
- **Your data**: category names (the seeded ones are English), counterparties,
  booking texts, sector names from fund files, the note saved with a snapshot.
- **Developer-facing API errors**: the validation messages routes return for requests
  the app itself never sends wrongly (about 100, e.g. "name is required"). The
  messages shown to a person are translated; to translate the rest, use `getT()` in
  the route.
- **Native widgets**: date and month pickers follow the browser's language, the
  desktop app's menu and the Windows installer are English.
- The month/day names and number formats do follow the language.

## Decisions to review with a native speaker

- **Address:** informal *du* / *tu* / *tu* throughout, matching the app's playful
  English. Banks and insurers often use *Sie* / *vous* / *Lei*; switching is a text
  change only.
- **German** uses Swiss spelling (*ss*, never *ß*; *Grösste*, *schliesst*) and
  «guillemets».
- **Gender:** German avoids it; French and Italian use *né(e)*, *prêt(e)*, *nato/a*,
  *pronto/a* where the sentence needs it.
- **Bank menus:** the export steps describe Raiffeisen's e-banking in each language
  (*Exporter*, *Esporta*); check the real menu names.
- **Dashboard:** *Übersicht* / *Tableau de bord* / *Cruscotto*.
